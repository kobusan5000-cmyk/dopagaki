# クラウド自動配信の設定(管理者向け)

PC を起動していなくても、dev2 が Drive に置いた ZIP が自動でテスターに届くようにします。

```
Drive の ZIP ─▶ Apps Script(Google 側・1分ごと)─▶ GitHub Actions「ingest」─▶ build ─▶ Release ─▶ テスターのランチャー
                         ▲                                         │
                         └──── 結果(公開 / 変更なし / 要確認 / 失敗)を見て ZIP を仕分け、配信状況.txt を更新
```

これまでの `publish.ps1`(この PC のタスク)と同じ判定を、GitHub 上で行います。
削除されるファイルがある ZIP は「要確認」に保留、ゲームにエラーがあれば公開しない、という安全装置もそのままです。

## 手順 1:GitHub のトークンを作る(1回だけ)
1. GitHub → 右上アイコン → **Settings** → 一番下の **Developer settings** → **Personal access tokens** → **Fine-grained tokens** → **Generate new token**
2. Token name: `dopagaki-drive`、Expiration: 1年(期限が切れる前に作り直します。期限の日付をメモしてください)
3. **Repository access** → *Only select repositories* → `dopagaki`
4. **Permissions → Repository permissions** → **Actions: Read and write**(他は触らない)
5. 作成後に表示される `github_pat_...` をコピーします(この画面を閉じると二度と見られません)。
   ※ このトークンは**秘密**です。チャットやリポジトリには貼らないでください。

## 手順 2:Apps Script を置く
1. Drive の共有フォルダを持っている Google アカウントで https://script.google.com を開き、**新しいプロジェクト**を作る。
2. `tools/cloud/drive-ingest.gs` の中身を全部コピーし、エディタの `コード.gs` に貼り付けて保存。
3. 左の歯車(**プロジェクトの設定**)→ **スクリプト プロパティ** → **プロパティを追加**
   - プロパティ: `GITHUB_TOKEN`
   - 値: 手順 1 のトークン
4. エディタに戻り、関数 `setup` を選んで **実行**。権限の確認が出たら承認します
   (「このアプリは確認されていません」と出たら、詳細 → 安全ではないページに移動、で進めます。自分で作ったスクリプトなので問題ありません)。
   → 実行ログに `OK. Folder: DOPA / trigger created.` と出れば完了です。1分ごとの自動実行が始まります。

## 手順 3:(任意)Discord に通知を出す
GitHub のリポジトリ → **Settings → Secrets and variables → Actions → New repository secret**
名前 `DISCORD_WEBHOOK`、値は `#不具合報告` の Webhook URL(作り方は `不具合報告の設定.md`)。
設定すると、公開・保留・失敗がクラウド側からも Discord に出ます。

## 手順 4:この PC のタスクを「クラウド優先」にする
この PC のタスク「DOPAGAKI Auto Publish」が同時に動くと、二重公開になります。
`tools\cloud-ingest.on`(空のファイル)を作ってください。

- あるあいだ、PC のタスクは**公開をしません**。PC が起動しているときに `最新版(読むだけ)\DOPAGAKI_latest.zip` を更新するだけです。
- PC を使った従来の方式に戻すときは、このファイルを消すだけです(Apps Script 側は `setup` で作ったトリガーを削除)。

## 動作確認
`ここにZIPを入れる` に ZIP を置いて、2〜4分待ちます。`配信状況.txt` に「公開しました: bNN」と出て、ZIP が `取り込み済み` に移れば成功です。
うまくいかないときは、GitHub の **Actions** タブ → `ingest` の最新の実行を開くと理由が見えます。

## 知っておくこと
- ZIP は、処理されるあいだだけ「リンクを知っている人が閲覧可」になり、終わると非公開に戻ります。
- ZIP の持ち主が dev2 のとき、Apps Script がファイルを移動・共有設定できるのは、あなたがそのフォルダの編集者である場合です。仕分けがされないときは、まずこれを確認してください。
- `最新版(読むだけ)` は、PC が起動しているときにしか更新されません。dev2 が急ぐときは、GitHub のリポジトリページ → **Code → Download ZIP** から最新を取れます。
- 直近の結果は Apps Script の「実行数」画面と、GitHub Actions の履歴に残ります。

# 追加機能:2人の修正を自動で合体する(2026-10-22)

## 仕組み
- 公開のたびに GitHub が「最新版ZIP」(`DOPAGAKI_latest.zip`)を作り、Release に付けます。中に **`BASE_VERSION.txt`**(どの版から作ったかの印)が入ります。
- Apps Script が、それを Drive の `最新版(読むだけ)` に自動でコピーします(5分おきに確認)。この PC が止まっていても動きます。
- 取り込み時、ZIP の `BASE_VERSION.txt` を見て **3者マージ**(出発点・今の最新版・ZIP の中身)をします(`ci/ingest-merge.sh`)。
  - 片方だけが変えた所 → そのまま採用 / 別々の場所を両方が変えた同じファイル(`main.gd` など)→ 合体 / 同じ場所を両方が変えた → `要確認` に保留(Discord にも通知)
  - `CHANGELOG.txt` は両方が先頭に追記するのが普通なので、相手の新しい塊を一番上、こちらのを次に並べて自動で解決します。
  - 印のない ZIP や、印の版が見つからない ZIP は、これまでどおり「丸ごと置き換え」です。
  - 元のファイルの半分以上が入っていない ZIP は、不完全とみなして保留します。
- ビルドに失敗した取り込みは、`main` から自動で取り消されます(以後のマージに壊れた版が残らないように)。

## 管理者の変更を ZIP で渡すとき
`powershell -File tools\make-zip.ps1` で作ります(`C:\Users\<あなた>\Downloads\DOPAGAKI_upload.zip`)。直接 `git push` しても構いません。

## あなたがやること(1回だけ)
1. Apps Script のエディタのコードを、`tools/cloud/drive-ingest.gs` の最新の全文に**貼り替えて保存**します(以前の「結果の読み直し」の修正と、最新版ZIPの自動コピーが入っています)。
2. 関数 `refreshStarterNow` を選んで **実行**します(最新版ZIPをすぐに Drive へコピーします。承認画面が出たら進めます)。
   ※ `setup` をやり直す必要はありません。

## テスト(自動テストの内容)
- `ci/test-ingest-merge.sh`(ローカルで `bash ci/test-ingest-merge.sh`):別々の場所の編集・同じ行・CHANGELOG・削除・追加・バイナリ・保護フォルダ・不完全ZIP・2回目アップロード・同じ変更、など 54 項目。
- GitHub 上の実運用テスト(`ingest.yml` の `target_branch` を使い、`main` を汚さない): 変更なし / 合体 / 衝突で保留 / 古い形式 / 保護フォルダ入り / 不完全ZIP / CRLF+バックスラッシュのZIP。
- 壊れたゲームを含む ZIP を `main` に流し、ビルド失敗 → 取り消し → リリースなし、を確認済み。
