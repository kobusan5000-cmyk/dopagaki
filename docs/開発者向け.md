# もう一人の開発者向け:成果物の渡し方(Git は使いません)

共有の Google Drive フォルダに **ZIP を1つ入れるだけ**です。
https://drive.google.com/drive/folders/1oAZwPnr_vquU7M55wKtLBHwI3ofXQX7S

## 毎回の流れ

1. **最新のファイルから始める**
   Drive の `最新版` フォルダ(または、前に渡された最新のZIP)を使って作業します。
   ※ 自分の古いコピーから作ると、相手の修正を消してしまいます。
2. Godot でいつも通り編集します。
3. `CHANGELOG.txt` の**一番上**に、今回の変更内容を書きます(下の「書き方」参照)。
4. プロジェクトのフォルダを **ZIP にします**(`.godot` フォルダは入れない)。
   - ZIP の名前は何でも構いません(例: `DOPAGAKI_0.9_日付.zip`)。
   - ZIP の中は、プロジェクトのフォルダが1つ入っている形でも、中身が直接入っている形でも大丈夫です。`project.godot` が1つだけ入っていれば構いません。
5. その ZIP を、**共有の Drive フォルダの一番上**に入れます。
6. 入れたら、あなたの相方(リポジトリの管理者)に **一声かけて**ください。確認のうえ、テスターに配信されます。

## CHANGELOG.txt の書き方

一番上に新しい変更を書き、**空行を1行**入れてから、前の内容を続けます。
一番上の塊(最初の空行まで)が、テスターの画面の「更新内容」に出ます。

```
DOPAGAKI v0.9
- ボスの体力を調整
- 畑の成長を速くした

DOPAGAKI v0.8 fix1
- (前の内容)
```

## 注意

- 複数の ZIP を入れたときは、**一番新しい1つだけ**が使われます。
- 取り込みが済んだ ZIP は、自動で `取り込み済み` フォルダに移動します。
- 2人が同じファイルを同時に編集すると、後から渡した方で上書きされます。**編集する前に相手に声をかけてください。**
- 管理者が確認画面で、消えるファイルや変更点の一覧を見ます。意図しない削除があれば相談します。

# 管理者向け(リポジトリを持っている人)

Drive に新しい ZIP が入ったら、**`tools\publish.bat` をダブルクリック**します。

1. Drive の一番新しい ZIP を読みます。
2. 現在の版との違い(追加・変更・削除されるファイル)と、テスターに出る更新内容を表示します。
3. `y` を入力すると、GitHub に載せて自動ビルドし、結果(b番号)を表示します。
4. 取り込んだ ZIP は `取り込み済み` フォルダに移動します。

確認だけしたいときは、コマンドで `tools\publish.ps1 -DryRun` を実行します(何も変更しません)。
