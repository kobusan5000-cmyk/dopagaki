# もう一人の開発者向け:成果物の渡し方(Git は使いません)

共有フォルダ **DOPA** の中の、**`ここにZIPを入れる`** フォルダに **ZIP を1つ入れるだけ**です。入れたら自動で取り込まれ、テスターに配信されます。
https://drive.google.com/drive/folders/1oAZwPnr_vquU7M55wKtLBHwI3ofXQX7S

## 毎回の流れ

1. **最新のファイルから始める**
   Drive の `最新版(読むだけ)` フォルダにある `DOPAGAKI_latest.zip` を展開して使います(公開のたびに自動で最新になります)。
   中に **`BASE_VERSION.txt`** が入っています。これは「どの版から作業を始めたか」の印で、**消さずにそのまま ZIP に入れて**ください。
   この印があると、あなたと相手が同じファイルを別々の場所で直していても、自動で合体されます。
2. Godot でいつも通り編集します。
3. `CHANGELOG.txt` の**一番上**に、今回の変更内容を書きます(下の「書き方」参照)。
   (`CHANGELOG_v0.12.3.txt` のように版ごとのファイルを足す形でも構いません。一番新しい版のファイルが更新内容として使われます)
4. プロジェクトのフォルダを **ZIP にします**(`.godot` フォルダは入れない)。
   - ZIP の名前は何でも構いません(例: `DOPAGAKI_0.9_日付.zip`)。
   - ZIP の中は、プロジェクトのフォルダが1つ入っている形でも、中身が直接入っている形でも大丈夫です。`project.godot` が1つだけ入っていれば構いません。
5. その ZIP を、**`ここにZIPを入れる`** フォルダに入れます(他のフォルダには入れません)。
6. 通常は2分ほどで公開されます(最大でも5分ほど)。結果は、同じフォルダの **`配信状況.txt`** に書かれます。

## フォルダの意味

| フォルダ・ファイル | 意味 |
|---|---|
| `ここにZIPを入れる` | **ZIP を入れるのはここだけ**(取り込み待ち) |
| `配信状況.txt` | 公開できたか、失敗したか、保留かが書かれる |
| `取り込み済み` | 公開が済んだ ZIP |
| `要確認` | **保留**された ZIP。同じ場所を2人が編集した、ファイルが大幅に足りない、などのときに止まります。管理者に声をかけてください |
| `失敗` | 公開に失敗した ZIP。ゲームに起動エラーがあった場合などです。`配信状況.txt` に理由が出ます |
| `古いZIP` | 同時に複数入れたときの、古い方 |
| `最新版(読むだけ)` | いつでも最新のプロジェクト(次の作業の出発点。`BASE_VERSION.txt` 入り)。読むだけで、ここには入れない。GitHub の Releases(最新の `DOPAGAKI_latest.zip`)からも取れます |

## CHANGELOG.txt の書き方

一番上に新しい変更を書き、**空行を1行**入れてから、前の内容を続けます。
一番上の塊(最初の空行まで)が、テスターの画面の「更新内容」に出ます。

```
DOPAGAKI v0.9
- ボスの体力を調整
- 畑の成長を速くした

DOPAGAKI v0.8 fix1
- (前の内容)
```

## 注意

- 配信の前に、自動でゲームを起動して**エラーがないか**確認されます。エラーがあると、テスターには配信されません(前の版のまま)。
- 管理者のパソコンが落ちていても、取り込まれます(クラウドで動いています)。
- 複数の ZIP を入れたときは、**一番新しい1つだけ**が使われます。
- **2人が同じファイルを同時に編集しても大丈夫です。** 別々の場所なら自動で合体します(`BASE_VERSION.txt` を入れたままにしていれば)。
- ただし **同じ行を2人が直した場合** は合体できず、`要確認` に止まります。管理者が対応します。
- **同じ最新版から2回目のアップロードをしない**でください。1回目が公開されたら、`最新版(読むだけ)` の ZIP を取り直して(公開から数分で入れ替わります)、そこから続けます。そうしないと、自分の1回目と重なって `要確認` になります。
- `BASE_VERSION.txt` が入っていない ZIP は、従来どおり「丸ごと置き換え」になります(古いコピーからだと相手の修正が消えます)。

# 管理者向け(リポジトリを持っている人)

- Drive に ZIP が入ると、Google の Apps Script が1分おきに見つけ、GitHub Actions(`ingest`)が取り込み・ビルド・公開をします。設定は `クラウド自動配信の設定.md`。
- **自分の変更も ZIP で渡す場合**は `powershell -File tools\make-zip.ps1` で作ります(`BASE_VERSION.txt` が入るので、相手の修正と合体できます)。直接 `git push` しても構いません。
- 保留(`要確認`)の ZIP は、中身を見て、相手に最新版から作り直してもらうか、手元で合体してから `git push` します。
- ビルドに失敗した取り込みは、自動で取り消されます(`main` は壊れません)。ZIP は `失敗` に入ります。
- 古い PC 方式(`tools\publish.bat`)は、`tools\cloud-ingest.on` を消すと使えます。
