# もう一人の開発者向け:成果物の渡し方(Git は使いません)

共有の Google Drive フォルダに **ZIP を1つ入れるだけ**です。入れたら自動で取り込まれ、テスターに配信されます。
https://drive.google.com/drive/folders/1oAZwPnr_vquU7M55wKtLBHwI3ofXQX7S

## 毎回の流れ

1. **最新のファイルから始める**
   Drive の `最新版` フォルダにある `DOPAGAKI_latest.zip` を展開して使います(配信のたびに自動で最新になります)。
   ※ 自分の古いコピーから作ると、相手の修正を消してしまいます。
2. Godot でいつも通り編集します。
3. `CHANGELOG.txt` の**一番上**に、今回の変更内容を書きます(下の「書き方」参照)。
   (`CHANGELOG_v0.12.3.txt` のように版ごとのファイルを足す形でも構いません。一番新しい版のファイルが更新内容として使われます)
4. プロジェクトのフォルダを **ZIP にします**(`.godot` フォルダは入れない)。
   - ZIP の名前は何でも構いません(例: `DOPAGAKI_0.9_日付.zip`)。
   - ZIP の中は、プロジェクトのフォルダが1つ入っている形でも、中身が直接入っている形でも大丈夫です。`project.godot` が1つだけ入っていれば構いません。
5. その ZIP を、**共有の Drive フォルダの一番上**に入れます。
6. 数分〜10分ほど待ちます。結果は、同じフォルダの **`配信状況.txt`** に書かれます。

## フォルダの意味

| フォルダ・ファイル | 意味 |
|---|---|
| (一番上の ZIP) | 取り込み待ち。ここに入れる |
| `配信状況.txt` | 公開できたか、失敗したか、保留かが書かれる |
| `取り込み済み` | 公開が済んだ ZIP |
| `要確認` | **保留**された ZIP。ファイルがいくつか消える内容など、古いコピーから作った疑いがあるときに止まります。管理者に声をかけてください |
| `失敗` | 公開に失敗した ZIP。ゲームに起動エラーがあった場合などです。`配信状況.txt` に理由が出ます |
| `古いZIP` | 同時に複数入れたときの、古い方 |
| `最新版` | いつでも最新のプロジェクト(次の作業の出発点) |

## CHANGELOG.txt の書き方

一番上に新しい変更を書き、**空行を1行**入れてから、前の内容を続けます。
一番上の塊(最初の空行まで)が、テスターの画面の「更新内容」に出ます。

```
DOPAGAKI v0.9
- ボスの体力を調整
- 畑の成長を速くした

DOPAGAKI v0.8 fix1
- (前の内容)
```

## 注意

- 配信の前に、自動でゲームを起動して**エラーがないか**確認されます。エラーがあると、テスターには配信されません(前の版のまま)。
- 管理者のパソコンが起動していて Drive が動いているときだけ、取り込まれます。
- 複数の ZIP を入れたときは、**一番新しい1つだけ**が使われます。
- 2人が同じファイルを同時に編集すると、後から渡した方で上書きされます。**編集する前に相手に声をかけてください。**

# 管理者向け(リポジトリを持っている人)

- Drive に ZIP が入ると、**5分おきに自動で**取り込み、GitHub に載せて、ビルドし、公開します(Windows のタスクスケジューラ「DOPAGAKI Auto Publish」)。
- 動かないときは `tools\publish.log` を見ます。
- 手動で確認したいときは、`tools\publish.bat` をダブルクリックします(違いの一覧を見て、`y` で公開)。`-DryRun` を付けると何も変更せずに確認できます。
- 保留(`要確認`)になった ZIP は、中身を見てから `tools\publish.bat` で公開するか、相手に作り直してもらいます。
- 自動実行を止めるには、タスクスケジューラで「DOPAGAKI Auto Publish」を無効にします。
